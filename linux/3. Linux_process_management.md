# Process Management in Operating Systems
A process can be thought as program in execution. A process will need certain resources - such as CPU time,memory, files and IO devices to accomplish the task. These resources are allocated to process either when it is created or while it is executing.
Process management is one of the core responsibilities of an operating system (OS). It involves creating processes, scheduling them for execution, resource allocation and managing communication between them, and ensuring their orderly termination.

---

## 1. Process Concept

### 1.1 What is a Process?

A **process** is an executing instance of a program. A program itself is just a file containing instructions and data, but when it is loaded into memory and begins execution, it becomes a process.

A process includes:
- The program code (text section)
- Current activity (Program Counter, registers)
- A stack containing temporary data (function parameters, return addresses, local variables)
- A data section where global variables are stored.
- A heap for dynamically allocated memory

Processes are fundamental to the design of modern operating systems, which allow multiple processes to be executed concurrently.

---

### 1.2 Process States

A process goes through different states during its lifetime:

- **New**: Process is being created.
- **Ready**: Process is loaded in main memory and waiting to be assigned to a CPU.
- **Running**: Instructions are being executed.
- **Waiting (Blocked)**: Process is waiting for an event (like I/O).
- **Terminated**: Process has finished execution.

Many operating systems also include intermediate or suspended states, especially in complex scheduling environments.

---

### 1.3 Process Control Block (PCB)

The **Process Control Block or task structure** is a data structure maintained by the OS for every process. It contains all the information needed to manage and schedule the process:

- **Process State**: Current state (running, waiting, etc.)
- **Program Counter**: Address of the next instruction
- **CPU Registers**: General-purpose and special-purpose registers
- **CPU Scheduling Information**: This information includes a process priority, pointers to scheduling queue and any other scheduling parameters.
- **Memory Management Info**: Page tables, segment tables
- **Accounting Info**: CPU usage, time limits, process ID
- **I/O Status**: List of I/O devices allocated like list of open files

The PCB acts as the "identity" of the process within the operating system.

---

### 1.4 Context Switch

A **context switch** occurs when the CPU switches from executing one process to another. During a context switch:

- The state of the current process is saved in its PCB.
- The state of the next scheduled process is loaded from its PCB.
- This allows processes to resume exactly where they left off.

Context switching introduces overhead, so operating systems try to minimize it while maintaining fairness and responsiveness.

---

## 2. Process Scheduling

The CPU is a limited resource, so the OS uses **schedulers** to manage which process gets the CPU and for how long.

---

### 2.1 Types of Schedulers

1. **Long-term Scheduler (Job Scheduler)**  
   - Controls the degree of multiprogramming by selecting which processes are admitted to the system for processing.
   - Invoked less frequently.

2. **Short-term Scheduler (CPU Scheduler)**  
   - Selects one of the ready processes to execute next on the CPU.
   - Invoked very frequently (milliseconds).

3. **Medium-term Scheduler**  
   - Temporarily removes processes from memory (swapping) to reduce the degree of multiprogramming.
   - Can later resume them.

---

### 2.2 Scheduling Queues

Processes are stored in various **queues**:

- **Job Queue**: Contains all processes in the system.
- **Ready Queue**: Holds all processes loaded in memory, ready to run.
- **Device Queue**: Holds processes waiting for a device (e.g., disk, printer).

Each queue may be implemented using linked lists and may be priority-based.

---

### 2.3 Dispatcher

The **dispatcher** is the component that gives control of the CPU to the process selected by scheduler.

Functions of a dispatcher include:
- Switching context
- Switching to user mode
- Jumping to the process’s next instruction

The time it takes to stop one process and start another is called **dispatch latency**.

---

## 3. Operations on Processes

### 3.1 Process Creation

Processes are typically created by other processes using system calls like `fork()` in UNIX.

- The **parent** process creates a **child** process.
- Each child can run the same or a different program.
- A tree of processes can result, forming a **process tree**.

Two execution possibilities after creation:
- The parent and child execute concurrently.
- The parent waits until the child finishes.

---

### 3.2 Process Termination

A process can terminate in two main ways:

- **Normal termination (exit)**: Process finishes its job and calls `exit()`.
- **Abnormal termination**: Due to errors, exceptions, or explicit kill signals.

A parent may also terminate a child for various reasons:
- Child exceeds resource limits.
- Child failed in execution.
- Parent is exiting, and OS policy is to kill all children.

---

## Conclusion

Process management is essential for building responsive and efficient operating systems. By understanding how processes are created, scheduled, managed, and terminated, one gains insight into the core of OS design.
